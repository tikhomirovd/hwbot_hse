# CONTEXT

Telegram-бот сбора ДЗ и оценки для 1 курса БАЦРФ (группы БАЦРФ261 и БАЦРФ262).
Это не LMS: регистрация по ведомости, рассылка работ, приём ссылок, посещаемость,
баллы и три числа оценки в прямом эфире.

Календарь и веса — в `data/course.toml`. Формулы — только в `src/hwbot/grading.py`.
Живая ведомость — `data/roster.csv` (не в git). Образец — `data/roster.example.csv`.

Публичный репозиторий: `https://github.com/tikhomirovd/hwbot_hse`.
Ветки и PR идут в `main`. Принять работу студента: `gh pr checkout N` и `gh pr merge`.
Локальный remote `backup` → `/root/backups/hwbot.git` (`git push backup HEAD`) —
архив со старыми хешами, на GitHub его не пушить.

## Где крутится

- Код: `/root/hwbot`
- Процесс: `systemd` юнит `hwbot.service`
- Токен и админы: `/root/hwbot/.env` (не коммитить, не логировать)
- SQLite: `/root/hwbot/data/bot.db`
- Список студентов: `/root/hwbot/data/roster.csv` (ФИО, группа, почта; seminar_group
  берётся из group_code: 261 / 262; без дат рождения)
- Бэкап базы: cron `17 4 * * * /root/hwbot/deploy/backup-db.sh` → `/root/backups/bot-YYYY-MM-DD.db`

Рестарт:

```bash
systemctl restart hwbot
systemctl status hwbot
journalctl -u hwbot -f
```

## Продукт

- Дедлайн общий для обеих групп. После срока бот ещё принимает работу до `accept_until`
  (неделя после дедлайна) и сам считает потолок балла: за каждые начатые сутки минус 1
  из 10, у ДЗ не ниже 4 в течение недели, позже — 0. Просрочку не храним, считаем на лету.
- `/hw` показывает только работы «сейчас на студенте»: `issued_at` наступил и приём ещё
  открыт. Невыданное — блоком «Скоро». Пока ничего не выдано, объясняется зачем бот,
  когда ДЗ-1 и что ПР пишутся на лекции.
- Любой текст вне диалога, пока приём открыт, бот предлагает принять как сдачу.
  Перед приёмом переспрашивает: репозиторий должен открываться без логина.
  Саму ссылку не проверяет. Если открыта одна работа, `/submit` сразу просит ссылку.
- После сдачи кнопка на карточке — «Обновить», не «Сдать».
- Пересдача после дедлайна поверх сдачи в срок требует подтверждения: потолок считается
  по последней отправке.
- Постоянной reply-клавиатуры нет. Команды + inline-кнопки.
- Две группы: `261` / `262`. Это и академические, и семинарские (261 — среда, 262 — суббота).
  В `course.toml` у семинаров `seminar_group = "261"` / `"262"`.
- Напоминания: окна 24ч, 12ч, момент дедлайна, каждый новый день просрочки,
  сутки до закрытия и закрытие. Уходят сразу, в том числе ночью.
  Пропущенные окна досылаются: `reached_windows` возвращает все наступившие.
  Новому студенту не шлём окна по работам, закрывшимся до его регистрации.
- Баллы через CLI не рассылаются: студент смотрит `/grade`.
- Преподаватель обычно не жмёт кнопки в Telegram: просит в Cursor «сделай рассылку» /
  «выгрузи» / «поставь баллы».

## Команды студентов

- `/start` — регистрация (ФИО или `@edu.hse.ru`) или профиль
- `/hw` — что сдавать прямо сейчас; кнопка «Сдать» / «Обновить» под карточкой
- `/submit` — сдать / пересдать; при одной открытой работе сразу просит ссылку
- `/mysubmissions` — свои сдачи и балл, если выставлен
- `/grade` — три числа с расшифровкой и разбивка в моноширинном блоке
- `/attendance` — сводка посещаемости; те же числа, что в `/grade`
- `/help`
- `/cancel`
- любой текст вне диалога — если приём открыт, предложит принять как сдачу

## Команды админа

- `/overview` — что требует внимания прямо сейчас: регистрация, работы в сдаче и
  проверке, незакрытая посещаемость, счётчики дел
- `/students` — кто зашёл в бота (N из M и список)
- `/students missing` — кто ещё не зарегистрировался
- `/status 1` — кто сдал
- `/missing 1` — кто не сдал
- `/export 1` — CSV

`/newhw` больше нет: элементы контроля живут в `course.toml`.

## Как делать рассылку, посещаемость и выгрузку из нового чата

Сначала прочитай этот файл. Потом из `/root/hwbot`:

```bash
uv run hwbot seed-course --dry-run
uv run hwbot seed-course

uv run hwbot attendance mark --lesson L03 --present "Иванов, Петрова"
uv run hwbot grade set --assessment hw1 --student "Иванов" --score 8.5
uv run hwbot gradebook --out /tmp/gradebook.csv

uv run hwbot broadcast --text "Семинар в субботу переносится"

uv run hwbot overview

uv run hwbot students
uv run hwbot students --registered
uv run hwbot students --missing
uv run hwbot unbind --student "Иванов"

uv run hwbot status --hw 1
uv run hwbot export --hw 1 --out /tmp/hw-1.csv
uv run hwbot list-hw
```

`hwbot students` без флага печатает `зарегистрировано N из M` и список тех, кто ещё не зашёл.

Дедлайн в `Europe/Moscow`.

## Выдача бота и ДЗ-1

1. Студентам: ссылка на бота + «напиши /start и ФИО как в ведомости или корпоративную почту».
2. 12.09.2026 в 12:30 ДЗ-1 становится текущей в `/hw`. Чтобы они узнали сами:
   `uv run hwbot broadcast --text "..."` или положиться на то, что зайдут в `/hw`.
   Готовый текст анонса: `formatting.new_homework_announcement` для hw1.
3. После первой ПР ноль за пропуск ставится руками: `grade set --assessment quiz1 --score 0`.

## Чего не делать

- Не логировать токен, сдачи, ФИО, почту и баллы
- Не класть в репозиторий и БД даты рождения
- Не показывать студенту чужие баллы, рейтинг или среднее по курсу
- Не дублировать формулу оценки вне `grading.py`
- Не добавлять постоянную клавиатуру
- Не коммитить `.env`, `data/bot.db` и живую `data/roster.csv`
